# Danta 자동 연구·모의투자

2026-10-02 사용자 요청: Codex 구독 잔여 사용량으로 6시간마다 연구·백테스트를 반복한다.
별도 OpenAI API 호출이나 유료 데이터 구매는 사용하지 않는다.

## 실행 흐름

1. Codex 예약 실행이 이 대화로 돌아와 사용량과 이전 실행 상태를 확인한다.
2. 실행 가능한 모든 관련 사용량 창에서 최소 20%를 남긴다. 사용량 조회 실패, 제한 도달,
   잔여 20% 미만이면 새 가설·코드 연구와 후보 선택을 건너뛴다. 한 번의 기동과 사용량
   확인 자체에도 사용량이 들 수 있으므로 정확한 토큰 잔액 기반 하드 한도는 아니다.
3. 실행기는 완료된 과거 거래일만 읽고 기존 분봉 엔진으로 최근 30일 모의투자를 재생한다.
   데이터가 없으면 `data_unavailable`을 기록한다. 예제·테스트 데이터를 실제 성과로 게시하지 않는다.
4. 최근 180일 범위에서 40거래일 학습 + 20거래일 후보 선택 구간으로 최대 6개 가설을 비교한다.
   후보 선택 구간도 연구에 사용된 데이터다. 이를 독립적인 검증 성과로 부르지 않는다.
5. 후보 하나를 선택하면 파라미터와 등록일을 고정한다. 등록일 이후 새로 쌓인 첫 10거래일을
   기다려 기준 전략과 같은 조건으로 평가한다. 과거 자료를 뒤늦게 수집해도 등록일 이전이면
   이 최종 검증에 쓸 수 없다. 대기 중에는 후보를 교체하거나 중간 성과를 보고 수정하지 않는다.
6. 통과한 후보만 **과거 데이터 모의투자용 기준 전략**으로 승격한다. 실패하면 기존 전략을 유지한다.
   검증 종료 기록은 게시보다 먼저 저장해 게시 실패 때문에 같은 검증을 재시도하지 않는다.
7. 실제 시세로 만든 모의투자 결과를 `publish/result.json`에 준비하고, 테스트 후 커밋·push하면
   GitHub Pages가 갱신된다. 같은 입력·후보이면 연구를 반복하지 않는다.

모의투자는 매 실행 시 동일한 초기 자본으로 과거 구간을 다시 재생하는 백테스트다.
실계좌나 증권사 모의계좌와 연결하지 않으며, 이전 실행의 수익을 다시 더해 누적하지 않는다.
수익률 개선이나 미래 수익을 보장하지 않는다.

## 채택 조건과 고정 조건

`research.json`이 검증 정책이고 `research/candidates.json`이 연구할 가설이다.
기본 조건은 순수익 양수, 기준 전략보다 0.5%p 이상 개선, KOSPI 초과,
청산 10건 이상, MDD 12% 이내, 기준 대비 MDD 악화 0.5%p 이내다.
추가로 편도 슬리피지 0.1%를 적용한 스트레스 검증에서도 순수익 양수·기준 이상이어야 한다.
기존 수수료와 세금은 동일하게 반영한다. 결측·비정상 가격·체결 품질 경고가 있으면 승격하지 않는다.
이 기준들은 연구의 운영 기준이며 통계적 유의성이나 장기 수익성을 입증하지 않는다.

자동 변경 범위는 진입·청산 채널 길이, 거래량·변동폭 필터, 진입 마감,
재진입 대기, 일일 진입 횟수다. 초기 자본, 종목, 포지션 비중, 손실 한도,
장 마감 청산, 비용과 검증 기준은 후보가 바꿀 수 없다.
기본 `config.yaml`을 덮어쓰지 않고 연구 상태 안의 모의투자 기준 전략만 갱신한다.

실행 엔진·평가 정책·고정 조건이 바뀌면 `context_changed`로 멈추고 기존 상태를 보존한다.
성능을 높이려고 검증 기준을 완화하거나 상태 파일을 삭제해 검증 이력을 초기화하지 않는다.
알고리즘 종류나 체결 모델을 바꾸는 개발은 별도 후보 브랜치에서 근거·테스트를 준비하고,
이전 기준 전략과의 비교 및 새 검증 계획을 검토한 후 별도 전환한다.

## 실제 데이터 준비

현재 복제본에는 실제 시세와 KIS DEV 자격 증명이 없다. 연구·모의투자 기능 검증은
테스트용 합성 데이터로 수행하며, 실데이터 연구가 실행됐다는 뜻은 아니다.

데이터가 있으면 `config.yaml`의 `output.cache_dir`로 연결한다.
수집에는 기존 KIS DEV 키 두 개가 필요하다. 저장소 루트의 `.env.example`을 참고해
로컬 `.env`를 준비하거나 `STOCK_SIM_ENV_FILE`로 기존 파일 경로를 지정한다.
키 값은 커밋하지 않는다. `--collect`는 DEV 과거 시세 조회만 수행한다.
최초 180일 분봉 수집은 시간이 걸리며, 성공한 분봉 캐시는 이후 실행에서 재사용한다.
현재 캐시 로더는 일봉 조회 구간과 일치하는 캐시 파일이 필요하므로,
이전 컴퓨터에서 가져온 다른 구간의 캐시만 있을 때는 일봉 재수집이 필요할 수 있다.

저장소 루트에서 실행:

```bash
# 사용량 조회 도구가 현재 58% 남았다고 확인한 경우의 예시. 값을 고정해서 예약하지 않는다.
PYTHONPATH=stock-sim/src uv run --frozen --project stock-sim \
  python -m stock_sim.research --remaining-percent 58

# DEV 설정이 준비된 뒤 누락된 과거 시세 수집과 게시할 결과 생성
PYTHONPATH=stock-sim/src uv run --frozen --project stock-sim \
  python -m stock_sim.research --remaining-percent 58 --collect --publish

# 잔여 사용량이 불명확하거나 부족할 때: 캐시로 과거 모의투자만 수행
PYTHONPATH=stock-sim/src uv run --frozen --project stock-sim \
  python -m stock_sim.research

uv run --frozen --project stock-sim pytest stock-sim/tests
```

`--end YYYY-MM-DD`로 완료된 과거 구간을 지정할 수 있다. 기본은 한국 시간 어제다.
오늘 이후 날짜는 거부한다. `--publish`는 파일을 준비하며 Git push는 하지 않는다.
결측·불완전 결과는 대시보드에 경고를 포함할 수 있고 전략 승격에는 사용하지 않는다.

## 상태·증거

- `data/research/latest.json`: 현재 상태, 데이터 기준일, 재생 결과 id
- `data/research/state.json`: 기준 전략, 고정 후보, 검증·승격 이력
- `data/research/rounds/*.json`: 각 연구 회차의 비교 수치
- `data/research/paper/<id>/`: 과거 모의투자 JSON·HTML
- `data/research/run.lock`: 중복 실행 방지. 비정상 종료 후 남았다면 실제 프로세스 종료를 확인한 뒤만 정리한다.

`data/`는 로컬 비공개 실행 상태다. 컴퓨터를 옮길 때 시세 캐시와 연구 상태를 함께
보존해야 검증 이력이 이어진다. Git 저장소를 복제하는 것만으로 이력은 복구되지 않는다.
상태 파일이 손상되면 덮어쓰지 않고 오류로 종료한다.

## Codex 자동 개발 실행 지침

한 회차의 목적은 검증 가능한 가설 하나를 연구·구현하거나 진행 중인 후보의 검증을
이어가는 것이다. 불필요한 문서·일반 리팩터링을 만드는 것으로 진행을 대신하지 않는다.

- 시작할 때 이 문서, `latest.json`, Git 상태를 확인한다. 다른 실행이나 사용자 변경이 있으면 겹치는 파일을 수정하지 않는다.
- 사용량 도구에서 `ordinaryUsageAllowed`, 사용량 제한 도달 여부, 모든 관련 창을 확인한다.
  각 창의 잔여 비율은 `100 - usedPercent`다. 알 수 없는 값을 100%로 간주하지 않는다.
  남은 크레딧·리셋 쿠폰을 사용하거나 API 결제로 전환하지 않는다. 최소 잔여 비율을 실행기에 전달한다.
- 한 회차에 가설 하나, 후보 최대 6개, 작업 시간 약 25분을 기본 상한으로 한다.
  사용량이 빠르게 줄면 현재 증거를 저장하고 종료한다.
- 기존 연구 코드·수치를 먼저 읽고, 필요한 경우 1차 자료로 가설을 조사해 후보 설명에 근거를 남긴다.
  아직 오지 않은 검증 기간에 맞춰 후보를 고정한다. 선택 데이터의 좋은 성과를 수익 증거로 과장하지 않는다.
- 실제 데이터가 없으면 자격 증명과 캐시의 존재만 확인한다. 그대로라면 같은 실패 호출과 가짜 성과 생성을 반복하지 않는다.
  구체적인 회귀 증거가 있을 때만 테스트·정확성 수정을 진행한다.
- 데이터가 있으면 실행기를 돌려 과거 모의투자를 갱신한다. DEV 설정이 있을 때만 `--collect`로 누락 시세를 수집한다.
  게시 파일은 실데이터 생성 성공 후만 갱신한다.
- 변경은 관련 테스트와 전체 오프라인 테스트를 통과해야 한다. diff에서 비용·자본·검증 기준의 우회와
  미래 데이터 누수를 확인한다. 통과한 후보/수정 및 실제 게시 결과만 `leerazor/danta`에 커밋·push한다.
  원격이 앞서 있거나 충돌하면 강제 push하지 않는다. CI와 배포 결과를 확인한다.
- 새로운 독립 검증 결과, 승격·회귀·실패·사용자 조치가 필요한 변화만 간결하게 알린다.
  상태가 그대로거나 새 데이터가 없는 경우에는 조용히 종료한다.

예약 실행에는 컴퓨터와 Codex 앱이 실행 중이어야 한다.
기존 WSL 파일시스템은 읽기 전용 오류가 관측됐으므로 현재 대화에서 확인한 Windows
복제 경로를 사용하고, 환경 문제가 지속되면 연구가 실행됐다고 보고하지 않는다.
