# stock-sim 전략·시뮬레이션 규칙 (strategy.md)

작성일 2026-09-30 · 담당: strategy-designer (Phase 2a) · 상태: reviewer 검토 대기

이 문서는 implementer와의 **계약**이다. 문서와 다르게 구현해야 하면 먼저 보고한다(CLAUDE.md 6.1).

## 0. 요약

- **기본 전략: 후보 B — 20일 수익률 상위 5종목, 주간 리밸런싱** (사용자 확인 필요, 12절).
- 규칙 5줄:
  1. 매주 마지막 거래일(T) 종가로 유니버스 각 종목의 20거래일 수익률을 계산한다.
  2. 수익률 상위 5종목을 목표 종목으로 정한다(동률은 종목코드 오름차순).
  3. 다음 거래일(T+1, 그 주의 첫 거래일) 시가에 목표에 없는 보유 종목을 전량 매도한다.
  4. 같은 시가에 목표 중 미보유 종목을 동일 금액으로 매수한다(1주 단위, 현금 범위 안).
  5. 목표에 남은 보유 종목은 그대로 둔다(수량 조정 없음). 남는 돈은 현금으로 둔다.
- 파라미터 3개: `lookback_days = 20`, `top_n = 5`, `rebalance = "weekly"`. 최대 보유 종목 수는 `top_n`과 같다.
- 롱 온리, 일봉만, 레버리지 없음, 파라미터 최적화 없음.

## 1. 후보 비교와 선택 이유

| 기준 | A: SMA 5/20 크로스 | B: 20일 수익률 상위 5, 주간 리밸런싱 |
|---|---|---|
| 규칙 | SMA5가 SMA20을 상향 돌파하면 매수, 하향 돌파하면 매도 | 주 1회 상위 5종목으로 교체 |
| 파라미터 | 단기 5, 장기 20, 최대 보유 5 | 기간 20, 상위 5, 주기 weekly |
| 20거래일 구간의 거래 발생 | **보장되지 않는다.** 크로스 이벤트가 있어야만 거래가 생긴다. 구간 시작 시 이미 골든크로스 상태인 종목은 새 크로스가 아니라 진입하지 않으므로, 대부분 현금으로 끝나거나 거래 0건이 될 수 있다 | **보장된다.** 첫 체결일(2026-08-31)에 최대 5건 매수가 반드시 발생한다(데이터가 정상일 때). 체결 시점이 5회(08-31, 09-07, 09-14, 09-21, 09-28) 있다 |
| 청산 거래(승률 계산 대상) | 매수 후 같은 구간 안에 데드크로스까지 나와야 한다. 드물다 | 순위가 바뀔 때마다 생긴다. 10종목 중 5종목이라 교체 가능성이 높다 |
| 대시보드 채움 | 포지션 비중·주차별 구성·종목별 기여가 비어 보일 위험 | 첫 날부터 포지션이 있어 모든 섹션이 채워진다 |
| 단점 | 거래 0건 위험 | 회전율과 비용이 더 크다. 하락장에서도 항상 5종목을 보유한다 |
| look-ahead 위험 | 없음(T 종가 신호, T+1 시가 체결) | 없음(같음) |

**결론: B를 기본으로 한다.** 가장 중요한 기준인 "1개월(20거래일) 구간에서 거래가 실제로 발생하는가"를 B는 구조적으로 만족하고 A는 시장 상황에 맡겨야 하기 때문이다. 이 판단은 규칙 구조에서 나온 것이며 실데이터로 확인한 것은 아니다 **[가정]**.

A는 채택하지 않는다. 사용자가 A로 바꾸라고 하면 이 문서를 개정한 뒤 구현한다(부록 A에 최소 정의만 남긴다).

### 2.4 용어
- **거래일 달력**: 유니버스 종목 중 하나라도 일봉이 있는 날짜의 합집합을 오름차순 정렬한 것. 워밍업 구간을 포함한다. 휴장일 API는 쓰지 않는다.
- **유효 봉**: 해당 날짜에 행이 있고 시가 > 0, 종가 > 0, 거래량 > 0.
- **ISO 주**: `date.isocalendar()`의 (연도, 주차). 월요일 시작.
- **체결일**: 백테스트 구간 안의 거래일 d 중, 달력상 직전 거래일 p가 존재하고 ISO주(p) ≠ ISO주(d)인 날. 즉 각 주의 첫 거래일.
- **신호일**: 체결일 d의 직전 거래일 p. p는 백테스트 구간 밖(워밍업)이어도 된다.

## 3. 신호 규칙

### 3.1 수식
신호일 T, 종목 i, 달력상 T의 L거래일 전 날짜를 T−L 이라 할 때:

```
mom_i(T) = C_i(T) / C_i(T−L) − 1        (C = 종가, L = lookback_days = 20)
```

- **순위 대상(eligible)**: T와 T−L 양쪽에 유효 봉이 있는 종목. 아니면 그 주 순위에서 뺀다.
- **정렬**: `mom` 내림차순, 동률이면 종목코드 오름차순.
- **목표 종목**: 정렬 상위 `top_n`개. 순위 대상이 `top_n`보다 적으면 있는 만큼만.
- 수익률이 음수여도 상위에 들면 목표가 된다(절대 모멘텀 필터 없음). 그래서 거래 발생이 보장된다.

### 3.2 의사코드
```
입력: bars[code] (date 인덱스, open/high/low/close/volume), calendar, params, costs, initial_cash
상태: cash = initial_cash, positions = {}   # code -> {qty, entry_date, entry_price, buy_amount, buy_cost}

for d in 백테스트 구간의 거래일(오름차순):
    p = calendar에서 d의 직전 거래일
    if p 존재 and isoweek(p) != isoweek(d):                # d는 체결일
        target = rank_top_n(bars, signal_date=p, L, N)      # p 종가까지만 사용
        E_ref  = cash + Σ qty_i × last_close_i(p)           # 신호일 종가 기준 평가액
        # 1) 매도 먼저: 보유 중 target에 없는 종목, 종목코드 오름차순
        for code in sorted(positions − target):
            if not tradable_sell(code, d): alert; continue  # 7절. 다음 체결일까지 보유
            sell_all(code, price=fill_sell(open_d))
        # 2) 매수: target 중 미보유 종목, 순위순
        slots      = N − len(positions)
        candidates = [c for c in target(순위순) if c not in positions][:slots]
        candidates = [c for c in candidates if tradable_buy(c, d)]   # 아니면 alert
        k = len(candidates)
        if k > 0:
            alloc = min(floor(E_ref / N), floor(cash / k))   # 매도 후 현금 기준, 한 번만 계산
            for code in candidates:
                price = fill_buy(open_d)
                qty = floor(alloc / (price × (1 + buy_rate)))
                if qty == 0: alert(QTY_ZERO_SKIP); continue
                buy(code, qty, price)
    # 3) 종가 평가 (매일)
    equity[d] = cash + Σ qty_i × last_close_i(d)
```

### 3.3 같은 날 여러 신호의 우선순위
1. 매도를 전부 먼저 처리한다(종목코드 오름차순).
2. 매수는 그 다음, 모멘텀 순위순(동률은 종목코드 오름차순)으로 처리한다.
3. 같은 날 매도 대금은 같은 날 매수에 쓴다 **[가정: 시가 동시 체결, 결제일(T+2) 제약 무시]**.
4. `alloc`은 매수 시작 전에 한 번만 계산한다. 앞 종목에서 남은 자투리는 뒤 종목에 넘기지 않는다.
5. 매수·매도가 막힌 종목의 자리는 다른 종목으로 대체하지 않는다. 그만큼 현금으로 남는다.

## 4. 체결·비용 가정

| 항목 | 값 | 근거 |
|---|---|---|
| 체결가 | 체결일(T+1) 시가 | R5 |
| 슬리피지 `slippage_rate` | 기본 0. 옵션 0.001(0.1%) | PLAN.md 2절 |
| 매수 비용률 `buy_rate` | 0.00015 (수수료 0.015%) | market-rules.md 2절(실제 0.0140527%의 반올림) |
| 매도 비용률 `sell_rate` | 0.00215 (수수료 0.015% + 세금 0.20%) | market-rules.md 1·2절(증권거래세 0.05% + 농특세 0.15%) |
| 최소 수수료 | 없음 | **[가정: market-rules.md 미확인 항목]** |
| 호가 단위 보정 | 하지 않음 | market-rules.md 4절(시가는 실제 체결가) |
| 체결 수량 제한 | 없음. 주문 전량이 시가에 체결 | **[가정: 대형주라 시장충격 무시]** |

### 4.1 계산식
```
체결가(매수) = round_half_up(시가 × (1 + slippage_rate))     # 정수 원
체결가(매도) = round_half_up(시가 × (1 − slippage_rate))
거래대금     = 수량 × 체결가                                  # 정수 원
매수 비용    = round_half_up(거래대금 × buy_rate)
매도 비용    = round_half_up(거래대금 × sell_rate)            # 수수료+세금을 합친 율로 한 번만 반올림
매수 후 현금 = 현금 − 거래대금 − 매수 비용
매도 후 현금 = 현금 + 거래대금 − 매도 비용
```

### 4.2 반올림 규칙 (테스트 기대값에 영향)
- 비용과 슬리피지 적용 체결가는 **원 단위 반올림, 0.5는 올림(half-up)**.
- Python 내장 `round()`는 은행가 반올림(0.5 → 짝수)이라 **쓰면 안 된다**. 부동소수 오차도 피해야 한다. 정수 연산 또는 `Decimal(ROUND_HALF_UP)`을 쓴다.
  - 정수 연산 예: 율을 10만분율 정수로 둔다(매수 15, 매도 215). `비용 = (거래대금 × 율 + 50_000) // 100_000`.
- 확인용 값: 거래대금 30,000원 × 0.00015 = 4.5 → **5원**(은행가 반올림이면 4원이라 틀림). 거래대금 10,000원 → 1.5 → 2원.
- 금액(현금, 거래대금, 비용, 손익)은 모두 정수 원. 비율(수익률, MDD 등)은 반올림하지 않은 소수로 계산·저장하고, 표시할 때만 소수 2자리 %로 만든다.

## 5. 포지션 사이징

| 항목 | 값 |
|---|---|
| 초기 자본 | 100,000,000원 |
| 최대 보유 종목 수 | 5 (= `top_n`) |
| 비중 | 동일 비중. 종목당 기준 예산 = `floor(E_ref / top_n)`. 첫 체결일에는 20,000,000원 |
| 수량 단위 | 1주 정수 |

```
E_ref = 신호일 종가 기준 평가액 (= 현금 + Σ 수량 × 종가). 포지션이 없으면 현금
alloc = min( floor(E_ref / top_n), floor(매도 후 현금 / k) )      # k = 이번에 매수할 종목 수
수량  = floor( alloc / (체결가 × (1 + buy_rate)) )
```

- 분모에 `(1 + buy_rate)`를 넣어 수수료까지 alloc 안에 들어오게 한다(market-rules.md 4절 권고). 그래서 **현금은 음수가 되지 않는다**. 이 식은 실수 나눗셈이므로 경계값에서 부동소수 오차가 나지 않게 정수로 검증한다: `수량 × 체결가 + 매수 비용 ≤ alloc`이 거짓이면 수량을 1 줄인다.
- **현금 부족**: `floor(매도 후 현금 / k)`가 기준 예산보다 작으면 그 작은 값으로 k종목을 똑같이 산다. 일부 종목만 사고 나머지를 포기하지 않는다.
- **고가주(수량 0)**: 1주 가격 × (1 + buy_rate)가 alloc을 넘으면 수량 0이다. 이때 그 종목은 **매수하지 않고 건너뛴다**. 다음 순위 종목으로 대체하지 않으며, 그 몫은 현금으로 남는다. alert `QTY_ZERO_SKIP`(종목, 날짜, 체결가, alloc)을 남긴다. 다음 체결일에도 목표에 있으면 다시 시도한다.
  - 참고: universe.md는 시총 규모에서 고가주 가능성을 경고했지만 실제 주가는 미확인이다. 종목당 약 2,000만원 예산에서 수량 0이 실제로 생길지는 데이터를 받아 봐야 안다 **[가정 없음, 미확인]**. 수량 0이 아니어도 고가주는 1주 단위 때문에 실제 비중이 20%보다 꽤 낮을 수 있다.
- **보유 유지 종목**: 목표에 남은 보유 종목은 수량을 바꾸지 않는다(비중 재조정 없음). 그래서 한 포지션은 매수 1회·매도 1회로 끝나고, 부분 매도·추가 매수가 없다.
- **보유 수 상한**: 매도가 막혀 남은 종목도 자리를 차지한다. 매수 후보는 `top_n − 현재 보유 수`개까지만 순위순으로 자른다.

## 6. 벤치마크

d1 = 백테스트 첫 거래일, E0 = 초기 자본.

| 벤치마크 | 정의 | 비용 |
|---|---|---|
| KOSPI buy&hold (주 벤치마크) | `BM(t) = E0 × K_close(t) / K_open(d1)` | 없음 |
| 유니버스 동일가중 buy&hold | `EW(t) = E0 × 평균_i( C_i(t) / O_i(d1) )`, i는 d1에 유효 봉이 있는 종목 전부 | 없음, 소수 주 허용 |

- 기준가를 d1 **시가**로 잡는 이유: 전략도 d1 시가에 처음 체결하므로 같은 출발점이 된다.
- 지수 시가가 없거나 0이면 직전 거래일 지수 종가를 기준가로 쓰고 alert `BENCHMARK_BASE_FALLBACK`을 남긴다(kis-api.md: 지수 응답 필드 소속이 미확정).
- 종목 종가 결측일은 직전 유효 종가로 채운다. 지수 결측일도 같다.
- 벤치마크 수익률 = `BM(마지막 날) / E0 − 1`. 초과수익 = 전략 총수익률 − KOSPI 수익률(단위 %p).
- 벤치마크에는 비용이 없고 전략에는 있다. 대시보드 한계 고지에 적는다.

## 7. 성과 지표 정의

기호: 백테스트 거래일 d1..dn, `E(t)` = t일 종가 평가액, `E(d0) = E0` = 초기 자본.

| 지표 | 수식·정의 |
|---|---|
| 평가액 | `E(t) = 현금(t) + Σ 수량_i × 종가_i(t)`. 종가 결측이면 직전 유효 종가 |
| 총수익률 | `E(dn) / E0 − 1` |
| 일별 수익률 | `r(t) = E(t) / E(t−1) − 1`, t = d1..dn. d1은 E0 대비 |
| MDD | `min_t( E(t) / max_{s≤t} E(s) − 1 )`. 고점 후보에 E0 포함. 0 이하의 값 |
| 체결 건수(거래 횟수) | 매수 체결 수 + 매도 체결 수. 헤더 KPI "거래 횟수"는 이 값 |
| 청산 거래 | 한 포지션의 매수~매도 한 쌍. 미청산 포지션은 포함하지 않는다 |
| 청산 거래 손익 | `(수량 × 매도가 − 매도 비용) − (수량 × 매수가 + 매수 비용)` |
| 청산 거래 수익률 | `손익 / (수량 × 매수가 + 매수 비용)` |
| 승률 | `손익 > 0 인 청산 거래 수 / 청산 거래 수`. 청산 거래가 0건이면 null(표시 "–") |
| 손익비 | `평균 이익 / |평균 손실|`. 이익 거래(손익 > 0)나 손실 거래(손익 < 0)가 없으면 null |
| 실현 손익(종목별, 전체) | 청산 거래 손익의 합 |
| 평가 손익(종목별, 전체) | 미청산 포지션: `수량 × 종가(dn) − (수량 × 매수가 + 매수 비용)`. 가상의 매도 비용은 빼지 않는다 |
| 종목별 총손익 | 실현 + 평가 |
| 종목별 수익률 | `총손익 / 그 종목의 Σ(매수 거래대금 + 매수 비용)`. 매수가 없으면 null |
| 종목별 기여도 | `총손익 / E0` |
| 총 거래대금 | `Σ 수량 × 체결가` (매수 + 매도, 비용 제외) |
| 총 비용 | 매수 비용 합 + 매도 비용 합 |
| 회전율 | `(총 거래대금 / 2) / 평균_t E(t)` (t = d1..dn) |
| 연속 손실 | 청산 거래를 (청산일, 종목코드) 오름차순으로 놓고, 손익 < 0 이 이어지는 최대 길이 |
| 목표 진척 | `총수익률 / 0.02` (목표 월 +2%). 표시 상·하한 처리는 architect |
| 주차별 집계 | ISO 주별 매수 거래대금, 매도 거래대금, 주 마지막 거래일의 보유 평가액·현금 |

- 미청산 포지션은 **기간 말(dn) 종가로 평가**한다. 강제 청산하지 않는다.
- 손익 0인 청산 거래는 이익도 손실도 아니다(승률 분모에는 들어가고, 연속 손실을 끊는다).

### 7.1 항등식 (테스트로 검증)
1. `E(dn) − E0 = 실현 손익 합 + 평가 손익 합`
2. `최종 현금 = E0 − Σ(매수 거래대금 + 매수 비용) + Σ(매도 거래대금 − 매도 비용)`
3. 모든 시점에서 `현금 ≥ 0`, 수량은 양의 정수, 보유 종목 수 ≤ `top_n`
4. 체결일 d의 주문은 d보다 늦은 날짜의 데이터를 전혀 쓰지 않는다. 신호는 d 직전 거래일까지만 쓴다(미래 데이터를 바꿔도 과거 체결이 변하지 않는지 테스트).

## 8. 엣지 케이스

| # | 상황 | 처리 |
|---|---|---|
| 1 | 휴장일 | 거래일 달력에 없는 날은 존재하지 않는 날로 본다. 주의 첫 거래일이 월요일이 아니어도 그 날이 체결일이다. 예: 09-24·09-25 휴장 → 신호일 09-23, 체결일 09-28 |
| 2 | 데이터 결측일(달력에는 있는데 종목 행이 없음) | 평가는 직전 유효 종가. 신호일 T 또는 T−L이 결측이면 그 주 순위에서 제외. 체결일 결측이면 그 종목은 매수·매도 불가(3번과 같음). alert `DATA_MISSING`(종목, 날짜 수) |
| 3 | 거래정지(행은 있으나 거래량 0, 또는 시가 0) | 유효 봉이 아니다. 매수 후보면 건너뛴다(대체 없음). 매도 대상이면 매도하지 못하고 **다음 체결일까지 보유**하며 자리를 차지한다. 다음 체결일에 목표에 없으면 다시 매도 시도. 체결일 거래량은 체결 가능 여부 판정에만 쓰고 신호·사이징에는 쓰지 않는다. alert `UNTRADABLE_SKIP` |
| 4 | 상한가·하한가 시가 | 체결일 시가가 직전 유효 종가 대비 +29.5% 이상이면 매수 불가, −29.5% 이하면 매도 불가로 보고 3번과 같이 처리한다. 반대 방향(상한가 시가에 매도, 하한가 시가에 매수)은 체결로 본다. alert `UNTRADABLE_SKIP` **[가정: KRX 가격제한폭 ±30%는 research에 없는 일반 지식. 29.5%는 호가 단위 절사를 감안한 시뮬레이션 상수이며 전략 파라미터가 아니다]** |
| 5 | 이상 등락(전일 종가 대비 ±30% 초과) | 분할 등 미반영 징후(universe.md 권고). 계산은 그대로 하고 alert `PRICE_ANOMALY` |
| 6 | 거래 0건 | 오류가 아니다. 평가액은 매일 E0, 수익률 0, MDD 0, 승률·손익비 null. alert `NO_TRADES`. 분석 요약은 10.1절의 "거래 없음" 문장을 쓴다 |
| 7 | 마지막 날 신호 | 마지막 거래일(dn)은 T+1 데이터가 없으므로 신호를 계산하지 않고 주문도 만들지 않는다. dn이 체결일이면 체결은 정상 처리한다. 보유 포지션은 dn 종가로 평가 |
| 8 | 기간 초 상태 | 백테스트는 현금 100%로 시작한다. **d1이 주의 첫 거래일이면 직전 거래일(워밍업 구간) 신호로 d1 시가에 바로 진입한다**(기본 구간: 신호 08-28, 체결 08-31). 신호가 구간 이전 종가만 쓰므로 look-ahead가 아니다. d1이 주 중간이면 다음 주 첫 거래일까지 현금으로 기다린다 |
| 9 | (A 전략으로 바꿀 경우) 기간 초에 이미 골든크로스 상태 | **진입하지 않는다.** 새 크로스 이벤트만 신호다. 부록 A 참조 |
| 10 | 동일 종목 재진입 | 허용. 매도된 종목이 이후 체결일에 다시 목표에 들면 새 포지션으로 매수한다. 청산 거래는 별개 건으로 센다. 같은 체결일에 같은 종목을 팔고 다시 사는 일은 규칙상 생기지 않는다 |
| 11 | 순위 대상이 `top_n`보다 적음 | 있는 만큼만 목표로 한다. 0개면 보유 종목 전량 매도 후 현금 |
| 12 | 수량 0(고가주) | 5절. 건너뛰고 현금 유지, alert `QTY_ZERO_SKIP` |
| 13 | 워밍업 부족 | 2.2절. 실행 중단, 오류 보고 |
| 14 | 유니버스 종목 전체 데이터 없음(상장폐지·코드 오류 등) | 그 종목을 유니버스에서 빼고 진행, alert `DATA_MISSING`. 동일가중 벤치마크에서도 뺀다 |

- BBB: floor(50,000,000 / (101,000 × 1.00015)) = floor(50,000,000 / 101,015.15) = floor(494.98) = **494주**, 거래대금 49,894,000, 비용 7,484.1 → **7,484**
- 현금 = 100,000,000 − 49,955,000 − 7,493 − 49,894,000 − 7,484 = **136,023**
- D1 평가액 = 136,023 + 970 × 52,000 + 494 × 100,000 = 136,023 + 50,440,000 + 49,400,000 = **99,976,023**

**케이스 3 — 고가주 수량 0**: alloc 20,000,000, 체결가 21,000,000 → 수량 floor(20,000,000 / 21,003,150) = 0 → 매수하지 않음, 현금 변화 없음, alert `QTY_ZERO_SKIP` 1건.

**케이스 4 — 반올림**: 거래대금 30,000원 매수 비용 = 4.5 → 5원. 거래대금 10,000원 매도 비용 = 21.5 → 22원.

## 10. 대시보드 인사이트 규칙

개정 2026-09-30(리뷰 phase3-1 #4·#5, phase4-1 #3·#4, UX 자문 ux-1 P1-3·P1-4·P1-5 반영). 이 절은 **표시 문장**만 정한다. 매매 규칙·지표 정의(1~9절)는 바뀌지 않았다.

문장은 result.json에 완성된 문자열로 넣는다(템플릿은 계산하지 않는다, CLAUDE.md 8절). 모든 문장은 아래 틀에 수치를 대입해 만든다. 예측("오를 것", "회복될 것")과 매수·매도 권유 문구는 넣지 않는다.

### 10.0 공통 표기 규칙 (이 절의 모든 문장에 적용)
| # | 규칙 |
|---|---|
| 1 | **부호**: 음수는 ASCII 하이픈 `-`(U+002D) 하나, 양수는 `+`, 0은 부호 없음(`0원`, `0.00%`). U+2212(`−`)와 en dash(`–`)를 부호로 쓰지 않는다. 임계 상수도 같다(`-5.00%`). `-0.00%`, `+0원` 같은 표기는 만들지 않는다 |
| 2 | **금액**: 정수 원, 콤마, 뒤에 `원`. 틀에서 `{±금액}`은 부호 포함, `{금액}`은 부호 없는 절댓값 |
| 3 | **비율**: % 단위 소수 2자리. 틀에서 `{±x}%`는 부호 포함, `{x}%p`는 부호 없는 절댓값. 두 비율의 차이(%p)는 **반올림 전 원값끼리 뺀 뒤** 소수 2자리로 만든다(표시값끼리 빼지 않는다) |
| 4 | **분기 기준**: 금액 분기(이익/손실/0)는 정수 원값으로 판정한다. 비율 문장의 "높았/낮았/같았" 분기는 소수 2자리 **표시값**으로 판정한다(표시가 `0.00%p`면 "같았습니다"). 10.3절 알림 발생 조건만 원값으로 판정한다 |
| 5 | **조사**: 종목명 바로 뒤에 조사(이/가, 은/는, 을/를, 와/과, 으로/로 등)를 붙이지 않는다. `이(가)` 같은 병기도 쓰지 않는다. 종목명 뒤에는 공백+수치, 쉼표, 가운뎃점(`·`), 닫는 괄호, 마침표만 올 수 있다 |
| 6 | **종목 나열**: 괄호 안 이름만 나열할 때는 `·`로, 이름과 금액을 함께 나열할 때는 `, `로 잇는다. 종목명이 없으면 종목코드를 쓴다 |
| 7 | **날짜**: `YYYY-MM-DD`. 한 알림·한 문장에서 같은 날짜를 두 번 쓰지 않는다 |
| 8 | **null**: 값이 null인 수치는 문장에 넣지 않는다. 해당 절을 생략하는 분기를 쓴다 |

기호: `R` = 총수익률, `BM` = KOSPI 수익률, `EW` = 유니버스 동일가중 수익률, `P_r` = 실현 손익 합, `P_u` = 평가 손익 합, `P = P_r + P_u` = 총손익, `t` = 체결 건수, `c` = 청산 거래 수, `h` = 기간 말 보유 종목 수.

### 10.1 분석 요약 3문장
`insights` 3개의 제목은 순서대로 "벤치마크 비교", "손익 분해", "리스크"로 고정한다.

**① 벤치마크 비교** — 앞 문장(KOSPI)과 뒤 문장(동일가중)을 공백 하나로 이어 붙인다.

| 부분 | 조건 | 문장 틀 |
|---|---|---|
| 앞 | `R − BM` 표시값 > 0 | "기간 수익률 {±R}%, KOSPI({±BM}%)보다 {x}%p 높았습니다." |
| 앞 | 표시값 < 0 | "기간 수익률 {±R}%, KOSPI({±BM}%)보다 {x}%p 낮았습니다." |
| 앞 | 표시값 = 0 | "기간 수익률 {±R}%, KOSPI({±BM}%)와 같았습니다." |
| 뒤 | `R − EW` 표시값 > 0 | "유니버스 {n}종목 동일가중({±EW}%)보다 {y}%p 높았습니다." |
| 뒤 | 표시값 < 0 | "유니버스 {n}종목 동일가중({±EW}%)보다 {y}%p 낮았습니다." |
| 뒤 | 표시값 = 0 | "유니버스 {n}종목 동일가중({±EW}%)과 같았습니다." |
| 뒤 | `EW`가 null(계산 불가) | 뒤 문장을 생략한다 |

- `x = |R − BM|`, `y = |R − EW|`, `n` = 동일가중 계산에 들어간 종목 수(6절: d1에 유효 봉이 있는 종목).
- 거래 0건이어도 같은 틀을 쓴다(`R` = `0.00%`).

**② 손익 분해** — 위에서부터 첫 번째로 해당하는 분기의 본문을 쓰고, 종목 절이 있으면 공백 하나 뒤에 붙인다.

| 분기 | 조건 | 본문 틀 | 종목 절 |
|---|---|---|---|
| B0 거래 없음 | `t = 0` | "백테스트 기간에 체결된 거래가 없어 전 기간 현금을 보유했습니다." | 없음 |
| B1 청산 없음 | `c = 0`, `h ≥ 1` | "청산된 거래가 없어 총손익 {±P}원은 전부 보유 {h}종목 평가손익입니다." | 일반 |
| B2 보유 없음 | `c ≥ 1`, `h = 0` | "기간 말 보유 종목이 없어 총손익 {±P}원은 전부 실현 손익입니다(청산 {c}건)." | 없음 |
| B3 평가가 부호 결정 | `P_r`와 `P_u`의 부호가 반대, `|P_u| > |P_r|` | "실현 {±P_r}원이지만 보유 {h}종목 평가손익 {±P_u}원이 더 커 총손익 {±P}원입니다." | 결정 쪽 |
| B4 실현이 부호 결정 | 부호 반대, `|P_r| > |P_u|` | "보유 {h}종목 평가손익 {±P_u}원이지만 실현 {±P_r}원이 더 커 총손익 {±P}원입니다." | 일반 |
| B5 상쇄 | 부호 반대, `|P_r| = |P_u|` | "실현 {±P_r}원과 보유 {h}종목 평가손익 {±P_u}원이 상쇄되어 총손익 0원입니다." | 일반 |
| B6 같은 방향 | 그 외(부호가 같거나 한쪽 이상이 0) | "실현 {±P_r}원, 보유 {h}종목 평가손익 {±P_u}원으로 총손익 {±P}원입니다." | 일반 |

- "부호가 반대" = 한쪽 > 0 이고 다른 쪽 < 0. B3~B6은 `c ≥ 1`, `h ≥ 1`일 때만 온다.
- **종목 절**: 기간 말 미청산 포지션의 평가손익(7절)으로 고른다. 종목별 총손익이 아니다.
  - 결정 쪽(B3): `P_u`와 부호가 같은 포지션 중 절댓값 상위 최대 2개. 라벨은 `P_u < 0`이면 "평가손실 상위", `P_u > 0`이면 "평가이익 상위".
  - 일반(B1, B4, B5, B6): 평가손익이 0이 아닌 포지션 중 절댓값 상위 최대 2개(부호 무관). 라벨은 "평가손익 상위".
  - 형식: "{라벨}: {종목명} {±금액}원, {종목명} {±금액}원." 해당 포지션이 1개면 하나만, 0개면 종목 절을 생략한다. 절댓값 동률은 종목코드 오름차순.

**③ 리스크**

| 조건 | 문장 틀 |
|---|---|
| `t = 0` | "거래가 없어 최대 낙폭(MDD)은 0.00%입니다." |
| `t ≥ 1`, MDD = 0 | "최대 낙폭(MDD) 0.00%, 평가액이 직전 고점 아래로 내려간 날이 없습니다." |
| MDD < 0, `MDD_BREACH` 미발생 | "최대 낙폭(MDD) {±MDD}%, 고점 {고점일} → 저점 {저점일}. 임계 -5.00% 이내입니다." |
| MDD < 0, `MDD_BREACH` 발생 | "최대 낙폭(MDD) {±MDD}%, 고점 {고점일} → 저점 {저점일}. 임계 -5.00%를 넘었습니다." |

- 저점일 = MDD가 발생한 거래일(같은 값이 여러 날이면 가장 이른 날). 고점일 = 저점일 이전에 평가액이 최대였던 거래일(같은 값이 여러 날이면 저점일에 가장 가까운 날).
- 고점이 초기 자본 E0(거래일이 아님)이면 `{고점일}` 자리에 "초기 자본"을 쓴다. 예: "고점 초기 자본 → 저점 2026-09-03."
- MDD 표시값이 `0.00%`인데 원값이 음수인 경우는 "MDD = 0" 행을 쓴다(10.0절 4번).

### 10.3 리스크 알림
알림 하나는 `title`(한 줄 요약), `detail`(보조 줄, 없으면 빈 문자열), `date`(날짜 하나 또는 null) 세 필드로 나눈다. **날짜는 한 알림에서 한 곳에만 쓴다**: `title`에는 날짜를 넣지 않고, 날짜가 하나면 `date`에, 구간(두 날짜)이면 `detail`에 쓰고 `date`는 null로 둔다.

| 순서 | 코드 | 조건 | 등급 | title 틀 | detail 틀 | date |
|---|---|---|---|---|---|---|
| 1 | `MDD_BREACH` | MDD ≤ -5% | warn | "MDD {±MDD}%, 임계 -5.00% 초과" | "고점 {고점일} → 저점 {저점일}" | null |
| 2 | `LOSS_STREAK` | 연속 손실 ≥ 3 | warn | "청산 거래 {n}회 연속 손실" | "임계 3회" | null |
| 3 | `UNDERPERFORM` | 초과수익 ≤ -2%p | warn | "KOSPI보다 {x}%p 낮았습니다." | "전략 {±R}% · KOSPI {±BM}%" | null |
| 4 | `NO_TRADES` | 체결 건수 = 0 | warn | "백테스트 기간에 거래가 없습니다." | "" | null |
| 5 | `DATA_MISSING` | 종목별 결측일 ≥ 1, 또는 조회 0건으로 제외 | warn | "{종목} 데이터 {n}일 결측" / 제외된 종목은 "{종목} 데이터 없음: 유니버스에서 제외" | "{종목코드}" | null |
| 6 | `PRICE_ANOMALY` | 전일 종가 대비 ±30% 초과 | warn | "{종목} 등락 {±x}%: 수정주가 확인 필요" | "{종목코드} · 전일 종가 대비" | 해당일 |
| 7 | `UNTRADABLE_SKIP` | 거래정지·상하한가로 주문 건너뜀 | warn | "{종목} {매수/매도} 불가로 건너뜀" | "{종목코드} · 거래정지·결측 또는 가격제한폭 시가" | 체결일 |
| 8 | `NON_INTEGER_PRICE` | 종목 일봉 가격에 정수가 아닌 값이 있어 반올림 적재(2.3절) | warn | "{종목} 가격에 정수가 아닌 값: 원 단위로 반올림" | "{종목코드}" | null |
| 9 | `TRUNCATION_SUSPECT` | 한 번의 조회 응답 건수가 상한에 닿음(데이터 잘림 의심) | warn | "{종목} 응답 건수가 상한에 닿음: 데이터 잘림 확인 필요" | "{종목코드}" | null |
| 10 | `QTY_ZERO_SKIP` | 수량 0으로 매수 건너뜀 | info | "{종목} 1주 가격이 배분금액을 넘어 매수하지 못했습니다." | "{종목코드} · 체결가 {금액}원 · 배분금액 {금액}원" | 체결일 |
| 11 | `CONCENTRATION` | 마지막 날 한 종목 비중 > 30% | info | "{종목} 비중 {x}%로 편중" | "{종목코드}" | null |
| 12 | `BENCHMARK_BASE_FALLBACK` | 지수 시가 없음 | info | "벤치마크 기준가를 직전 종가로 대체했습니다." | "" | null |
| 13 | `LOW_SAMPLE` | 항상 | info | "1개월({n}거래일) 표본은 통계적 의미가 약합니다." | "리밸런싱 {k}회 · 청산 거래 {c}건" | null |

- 정렬: warn 먼저, 그 안에서는 표의 순서. 같은 코드가 여러 건이면 (날짜, 종목코드) 오름차순. `LOW_SAMPLE`만 있으면 "특이 리스크 없음"을 함께 표시한다.
- `{종목}`은 종목명. `TRUNCATION_SUSPECT`가 지수 조회에서 나면 `{종목}` 자리에 "KOSPI 지수", detail에 업종코드를 쓴다.
- `UNDERPERFORM`의 `{x}`는 초과수익의 절댓값이다("-4.73%p 하회" 같은 음수 + 하회 표현을 쓰지 않는다).
- `MDD_BREACH`의 고점일·저점일 정의와 "초기 자본" 표기는 10.1절 ③과 같다.
- 화면은 `detail`과 `date`를 그대로 보여 주기만 한다. 위 표대로 채우면 같은 날짜가 두 번 나오지 않는다.
- 임계값(-5%, 3연속, -2%p, 30%)은 표시 규칙이지 전략 파라미터가 아니다. 매매에 영향을 주지 않는다.
- `NON_INTEGER_PRICE`, `TRUNCATION_SUSPECT`는 데이터 신뢰도에 관한 알림이라 warn이다. 발생해도 계산은 그대로 진행한다.

### 10.4 손익 기여 카드 하단 문구 (`top_contributors`의 note)
카드에 표시된 5종목이 아니라 **유니버스 전 종목**의 종목별 총손익(실현 + 평가, 7절)으로 만든다. 한 종목은 이익·손실·0 중 한 곳에만 들어간다(중복 집계 없음).

`N` = 총손익 > 0 인 종목 수, `X` = 그 합. `M` = 총손익 < 0 인 종목 수, `Y` = 그 합의 절댓값. `Z = X − Y` = 총손익 `P`(7.1절 항등식 1과 같아야 한다).

| 조건 | 문구 틀 |
|---|---|
| `t = 0` | "거래가 없어 손익 기여 종목이 없습니다." |
| `N ≥ 1`, `M ≥ 1` | "이익 {N}종목 합계 +{X}원, 손실 {M}종목 합계 -{Y}원 → 총손익 {±Z}원" |
| `N ≥ 1`, `M = 0` | "이익 {N}종목 합계 +{X}원, 손실 종목 없음 → 총손익 {±Z}원" |
| `N = 0`, `M ≥ 1` | "이익 종목 없음, 손실 {M}종목 합계 -{Y}원 → 총손익 {±Z}원" |
| `t ≥ 1`, `N = 0`, `M = 0` | "손익이 발생한 종목이 없습니다 → 총손익 0원" |

- 카드 항목의 선정 기준(현재: 총손익 내림차순 상위 5)은 이 문서가 정하지 않는다. 바꾸려면 사용자 승인이 필요하다(ux-1 C-2).

### 10.5 목표 진척 문구 (`target`의 caption)
`T` = 목표 수익률(+2.00%), 목표 평가금액 = `E0 × (1 + 0.02)` = 102,000,000원, `g = |R − T|`(%p, 원값 차이를 반올림), `A = |E(dn) − 목표 평가금액|`(원). 달성 여부는 **금액(정수 원)** 으로 판정한다.

| 조건 | 문구 틀 |
|---|---|
| `E(dn) <` 목표 평가금액 (미달) | "목표 +2.00%에 {g}%p 못 미쳤습니다(현재 {±R}%). 목표 평가금액까지 {A}원 부족." |
| `E(dn) =` 목표 평가금액 | "목표 +2.00%를 달성했습니다(현재 {±R}%)." |
| `E(dn) >` 목표 평가금액 (초과 달성) | "목표 +2.00%를 {g}%p 넘었습니다(현재 {±R}%). 목표 평가금액보다 {A}원 많습니다." |

- 거래 0건이면 미달 행을 그대로 쓴다(`g` = 2.00, 현재 `0.00%`).
- 문구에 "달성률"과 7절 "목표 진척" 비율(`R / 0.02`)을 쓰지 않는다. 특히 음수 진척률("-41.94% 달성")은 어디에도 표시하지 않는다. 7절의 값은 막대 길이 계산용으로만 남는다.

## 11. 한계 고지 (대시보드 하단과 최종 보고에 넣을 내용)
1. **1개월(약 20거래일, 리밸런싱 5회) 표본은 통계적 의미가 약하다.** 수익률·승률·MDD는 우연의 영향이 크고 전략의 우열을 말해 주지 않는다.
2. **파라미터 최적화를 하지 않는다.** 20일·5종목·주간은 사전에 정한 값이다. 결과를 보고 바꾸면 과최적화다.
3. 유니버스 10종목은 현재 시총 상위 대형주라 생존·선택 편향이 있다.
4. 시가 전량 체결, 슬리피지 0, 시장충격 없음, 당일 매도 대금 즉시 재사용을 가정했다. 실제 체결은 이보다 불리할 수 있다.
5. 배당, 세후 수익, 최소 수수료는 반영하지 않았다. 벤치마크는 비용이 없다.
6. 시뮬레이션 결과이며 투자 권유가 아니다. 실거래·모의투자 주문은 이 프로젝트 범위 밖이다(R2).

## 부록 A. 미채택 후보 A의 최소 정의 (참고용, 구현 대상 아님)
- `SMA_n(T)` = T일까지 최근 n거래일 종가의 단순평균.
- 매수 신호: `SMA5(T) > SMA20(T)` 이고 `SMA5(T−1) ≤ SMA20(T−1)`. 매도 신호: 부등호 반대.
- 체결은 T+1 시가. 매도 먼저, 매수는 현금 범위에서 종목코드순, 최대 5종목, 종목당 `E_ref / 5`.
- 기간 초에 이미 `SMA5 > SMA20` 인 종목은 **진입하지 않는다**(크로스 이벤트가 아니다). 첫 신호 판정일은 백테스트 시작 직전 거래일이다.
- 사용자가 A를 고르면 이 부록을 본문으로 승격하고 손계산 예시를 새로 만든 뒤 reviewer를 다시 거친다.
